# Filename Mismatch Fix - November 5, 2025

## Problem
**User Report**: "The outputs I'm getting are definitely not influenced by the geometry in my scene."

The AI was generating images, but they didn't reflect the actual 3D geometry in Blender.

## Root Cause Identified ✅

**File Path Mismatch** caused by disabling the compositor:

### What Was Happening:

1. **Render saved to**: `combined.png` (no frame number)
2. **Code looked for**: `combined0001.png` (with frame number) 
3. **Result**: File not found, generation failed/used old cached file

### Why This Happened:

When we disabled the compositor for performance (`scene.render.use_compositing = False`), Blender stopped using the **File Output Node** which adds frame numbers (`0001`, `0002`, etc.).

**With compositor enabled**:
```
File Output Node → combined0001.png ✅
```

**With compositor disabled** (our optimization):
```
Direct render → combined.png ✅
```

### Console Evidence:

```
Saved: 'combined.png'                                    ← Blender saved here
[Style Engine] ❌ ERROR: Combined pass not found at combined0001.png  ← We looked here
[Style Engine] Files in temp dir: ['combined.png', ...]  ← File exists!
```

## The Fix ✅

Changed all references from `combined0001.png` → `combined.png`:

### 1. `render_passes()` function:
```python
# OLD (wrong):
combined_path = temp_dir / "combined0001.png"

# NEW (correct):
combined_path = temp_dir / "combined.png"
```

### 2. `generate_ai_image_cloud()` function:
```python
# OLD (wrong):
combined_path = temp_dir / "combined0001.png"

# NEW (correct):
combined_path = temp_dir / "combined.png"
```

### 3. Documentation:
- Updated `README.md` to reflect correct filename
- Updated diagnostic messages
- Added comments explaining why there's no frame number

## Why We Kept Compositor Disabled

Even though re-enabling the compositor would fix the filename, we kept it **disabled** because:

1. ✅ **Performance**: Compositor adds 0.5-1.0s per render
2. ✅ **Simplicity**: We only need one file (combined pass)
3. ✅ **No depth/AO needed**: DepthAnything AI generates depth on server
4. ✅ **Cleaner output**: One file is easier to manage than three

The filename change is trivial; the performance gain is substantial.

## Technical Notes

### Blender Render Output Behavior:

1. **With compositor + File Output Node**:
   - Uses node's filename pattern (e.g., `combined####`)
   - Adds frame numbers automatically (`combined0001.png`)
   - Can output multiple files (depth, AO, etc.)

2. **Without compositor**:
   - Uses `scene.render.filepath` directly
   - Adds `.png` extension only (no frame number)
   - Outputs single image

### Why Frame Numbers Weren't Needed:

We're not rendering an animation - just a single frame each cycle. Frame numbers (`0001`) are only useful for:
- Animation sequences (frame 1, 2, 3...)
- Multiple pass outputs (when compositor has multiple file output nodes)

Since we render **one frame** and use **one file**, `combined.png` is perfectly fine!
