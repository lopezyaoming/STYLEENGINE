# Compositor Skip Fix - November 5, 2025

## Error
```python
KeyError: 'bpy_prop_collection[key]: key "Mist" not found'
```

Occurred in `setup_compositor()` when trying to access `render_layers.outputs['Mist']`.

## Root Cause

**Workbench doesn't support render passes!**

When we set Workbench as the default render engine in `setup_render_engine()`, the scene no longer has access to EEVEE/Cycles render passes like:
- Mist (depth proxy)
- Ambient Occlusion (AO)
- Z-depth
- Normal pass
- etc.

These are **EEVEE/Cycles-specific features**. Workbench only renders the viewport shading directly - no passes.

## The Conflict

1. `setup_render_engine()` sets: `scene.render.engine = 'BLENDER_WORKBENCH'` ✅
2. `setup_compositor()` tries to access: `render_layers.outputs['Mist']` ❌
3. **Boom!** Mist pass doesn't exist in Workbench

## The Solution

**Skip compositor setup entirely** - we don't need it anymore!

### Why We Don't Need the Compositor:

1. **Compositor disabled during render**:
   ```python
   scene.render.use_compositing = False  # Already disabled for performance
   ```

2. **Depth generated by AI**:
   - DepthAnything AI generates depth from the combined image
   - We don't send Blender's depth pass to the workflow
   
3. **AO not used**:
   - AO pass was never sent to the workflow
   - Only combined image is sent

4. **Performance**:
   - Compositor adds 0.5-1.0s overhead
   - File Output nodes add complexity

### Code Change:

```python
# OLD (caused error):
self.setup_compositor(context)

# NEW (skip it):
# Skip compositor setup - not needed with Workbench (no render passes)
# Compositor is disabled during rendering for performance anyway
# self.setup_compositor(context)  # DEPRECATED - Workbench doesn't support Mist/AO passes
```

## Historical Context

The compositor was originally set up when Style Engine used:
1. **EEVEE rendering** (had render passes)
2. **Multiple passes** (combined, depth, AO)
3. **File Output Nodes** (added frame numbers: `combined0001.png`)

Now we use:
1. **Workbench rendering** (no render passes)
2. **Single pass** (combined only)
3. **Direct file output** (`combined.png`)

The compositor became obsolete but was never removed - until now!

## Files Affected

### Before:
```
ai_vision/
  ├── combined0001.png  ← From File Output Node
  ├── depth0001.png     ← From File Output Node
  ├── ao0001.png        ← From File Output Node

### After:

  └── session.json
```

## Validation

Expected behavior after fix:
- [x] "Setup Workspace" completes without error
- [x] No compositor nodes created
- [x] No Mist/AO passes configured
- [x] Workbench renders successfully
- [x] `combined.png` created correctly

## Function Preserved

The `setup_compositor()` function is still in the code (commented out) in case we ever need it for:
- Future EEVEE/Cycles support
- Advanced render pass features
- Custom compositor workflows

But for the standard Workbench workflow, it's not needed.
