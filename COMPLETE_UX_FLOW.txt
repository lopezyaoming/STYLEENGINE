PART 1: OVERVIEW & INSTALLATION
================================================================================

1.1 WHAT IS STYLE ENGINE
-------------------------

Style Engine is a Blender addon that bridges 3D modeling and AI image generation.
It allows artists to:

• Generate AI images from Blender renders in real-time
• Project AI textures onto 3D objects
• Use reference images to guide AI generation (IPAdapter)
• Refine prompts using local LLM
• Navigate through generation history
• Create UV-mapped textures directly from 3D meshes

CORE VALUE PROPOSITION:
Instead of switching between Blender and external AI tools, Style Engine
integrates the entire workflow inside Blender's viewport, enabling rapid
iteration and creative exploration.


1.2 CORE CONCEPT
----------------

THE PIPELINE:
1. Model your scene in Blender (any geometry)
2. Position camera view
3. Write AI prompt in text editor
4. Generate AI image (uses render as base + ControlNet)
5. AI appears as camera background
6. Project onto objects or export
7. Iterate and refine

KEY INNOVATION:
The addon renders your scene (Workbench engine, fast), sends it to ComfyUI
with your prompt, and uses ControlNet (Canny + Depth) to maintain composition
while applying AI styling. The result appears as a camera background image
that you can view, project, or export.


1.3 INSTALLATION PROCESS
------------------------

STEP 1: Download/Clone Repository
→ User obtains the styleengine addon folder

STEP 2: Installation Methods

METHOD A: Development Mode (Symlink)
• Run `create_dev_link.ps1` (Windows, as Administrator)
• Creates symbolic link to addon folder
• Changes to source code reflect immediately in Blender

METHOD B: Manual Install
• Copy `scripts/addons/styleengine` folder
• Paste into Blender addons directory:
  Windows: C:\Users\<USER>\AppData\Roaming\Blender Foundation\Blender\<VERSION>\scripts\addons\
  macOS: ~/Library/Application Support/Blender/<VERSION>/scripts/addons/
  Linux: ~/.config/blender/<VERSION>/scripts/addons/

METHOD C: ZIP Install
• Package addon as styleengine.zip
• Blender → Edit → Preferences → Add-ons
• Click "Install..." → Select ZIP
• Enable addon checkbox

STEP 3: Enable Addon
• Open Blender
• Edit → Preferences → Add-ons
• Search: "Style Engine"
• Check the box to enable
• "Style Engine" tab appears in N-panel (3D Viewport sidebar)


1.4 INITIAL CONFIGURATION
--------------------------

FIRST RUN CHECKLIST:

1. Open Addon Preferences
   Edit → Preferences → Add-ons → Style Engine → Expand

2. Choose Backend
   • GCS (Self-Hosted): Enter ComfyUI server URL
   • RunComfy Cloud: Import credentials from file

3. Test Connection
   • Click "Test Connection" button
   • Verify green checkmark appears

4. Advanced Settings (Optional)
   • Set ComfyUI path (for UV texture feature)
   • Enable debug mode (for troubleshooting)
   • Configure download preferences

USER IS NOW READY TO USE THE ADDON

2.4 TEXT EDITOR (STYLEENGINE_Prompt)
-------------------------------------

LOCATION:
After running "Setup Workspace", a text editor area appears in the
workspace layout (typically bottom-right quadrant).

CONTENT:
The text editor shows the "STYLEENGINE_Prompt" text block with this default:

```
# Keywords
<k></k>
# Prompt
<p></p>
# Negative Prompt
<n></n>
```

USER INTERACTION:
• Type inside the <k></k> tags for keywords (optional)
• Type inside the <p></p> tags for main prompt (required)
• Type inside the <n></n> tags for negative prompt (optional)
• Comment lines (starting with #) are ignored
• Text is auto-synced during generation (no save button needed)

VISUAL FEATURES:
• Syntax highlighting enabled
• Word wrap enabled
• Line numbers disabled (cleaner view)
• Standard Blender text editor controls (zoom, search, etc.)

3.1 SETTING UP BACKEND
----------------------

SCENARIO: User has just installed and enabled the addon.

STEP-BY-STEP:

1. Open Preferences
   Menu: Edit → Preferences
   Tab: Add-ons
   Search: "Style Engine"
   
2. Expand Addon
   Click disclosure triangle next to addon name
   Preferences panel appears

3. Choose Backend
   
   OPTION A: Self-Hosted ComfyUI (GCS)
   • Select "GCS" from Backend dropdown
   • Enter server URL (e.g., http://34.145.107.158:8188)
   • Click "Test Connection"
   • Wait for green checkmark or error message
   
   OPTION B: RunComfy Cloud
   • Select "RunComfy Cloud" from dropdown
   • Click "Browse" next to Credentials File
   • Navigate to CREDENTIALS.txt file
   • Click "Import Credentials"
   • Credentials auto-populate
   • Click "Test Connection"
   • Wait for confirmation

4. Verify Success
   • Green checkmark icon appears
   • Status text: "Connected" or "Test Passed"
   • If error: Red message explains issue

USER NOW HAS WORKING BACKEND CONNECTION


3.2 CREATING AI VISION WORKSPACE
---------------------------------

SCENARIO: Backend is configured. User wants to start generating.

STEP-BY-STEP:

1. Open Any .blend File
   (Can be empty scene or existing project)

2. Position Your View
   • Navigate in 3D viewport to desired camera angle
   • This will become the AI camera view
   • Look at your geometry from interesting angle

3. Open Style Engine Panel
   • Press 'N' in 3D viewport (if sidebar not visible)
   • Click "Style Engine" tab

4. Click "Setup Workspace"
   EITHER:
   • Use button in N-panel (if visible)
   OR:
   • Press Alt+W → Click LEFT (Setup Workspace)

5. Wait 1-2 Seconds
   • Workspace transforms
   • Console shows progress messages

WHAT HAPPENS:
• New "AI" workspace tab appears at top
• Left viewport: Stays as-is (modeling)
• Right viewport: Splits into camera view (top) + text editor (bottom)
• Camera: "ai_camera" created and aligned to previous view
• Text editor: Shows STYLEENGINE_Prompt with template
• Background: Black placeholder image (current_ai.png)
• Temp directory: Created with session ID
• Console: Logs each step with ✓ checkmarks

USER NOW SEES DUAL-VIEWPORT LAYOUT


3.3 WRITING YOUR FIRST PROMPT
------------------------------

SCENARIO: Workspace is set up. User wants to write a prompt.

STEP-BY-STEP:

1. Locate Text Editor
   • Look at bottom-right area (below camera viewport)
   • Should show "STYLEENGINE_Prompt" text block
   • Default template visible:
     # Keywords
     <k></k>
     # Prompt
     <p></p>
     # Negative Prompt
     <n></n>

2. Add Keywords (Optional)
   • Click between <k> and </k>
   • Type comma-separated keywords
   • Example: <k>8k, concept art, detailed</k>

3. Write Main Prompt (Required)
   • Click between <p> and </p>
   • Type your image description
   • Example: <p>a medieval castle on a hill at sunset</p>

4. Add Negative Prompt (Optional)
   • Click between <n> and </n>
   • Type what you DON'T want
   • Example: <n>blurry, ugly, low quality</n>

5. (Optional) Refine with LLM
   • Focus on <p> tag content
   • Press Alt+W or open N-panel
   • Click "Refine Prompt (LLM)" button
   • Wait 3-10 seconds
   • Watch text editor update with enhanced prompt

EXAMPLE COMPLETE PROMPT:
```
# Keywords
<k>photorealistic, 8k, professional photography</k>
# Prompt
<p>a medieval stone castle perched on a hill at sunset, dramatic clouds, 
golden hour lighting, detailed stonework, surrounded by forest, 
cinematic composition</p>
# Negative Prompt
<n>blurry, low quality, ugly, deformed, cartoon, anime</n>
```

USER NOW HAS A COMPLETE PROMPT READY


3.4 GENERATING YOUR FIRST IMAGE
--------------------------------

SCENARIO: Prompt is written. User wants to generate.

STEP-BY-STEP:

1. Trigger Generation
   EITHER:
   • Press Alt+W → Click BOTTOM (Generate AI Quick)
   OR:
   • Use quick operator if registered (Shift+Alt+G)

2. Watch Console (Optional)
   • Window → Toggle System Console (Windows)
   • See real-time progress logs:
     [Style Engine] Rendering combined pass...
     [Style Engine] Using prompt: medieval stone castle...
     [GCS] Uploading combined.jpg...
     [GCS] ✓ Workflow submitted
     [Server API] Started polling...

3. Observe Status (in N-panel)
   • Status box appears (if in GCS mode)
   • Shows: "Generating: 3s" (updates every second)
   • Icon: Spinning animation (RENDER_ANIMATION)

4. Wait for Completion (5-30 seconds typical)
   • Server processes workflow
   • Polling checks every 2 seconds
   • Console shows:
     [GCS] Downloading final image...
     [GCS] ✓ Saved: current_ai.png
     [Style Engine] ✓ Image reloaded
     [GCS] ✓ Camera background updated

5. See Result
   • Camera viewport (right-top) updates automatically
   • AI image appears as camera background
   • Status changes to: "Ready" or "Idle"
   • Last generation time shown: "Previous: 12s"

WHAT JUST HAPPENED:
1. Addon rendered your scene (Workbench, fast)
2. Sent render + prompt to ComfyUI server
3. ComfyUI generated AI image using:
   - Your prompt
   - Canny edges (for composition)
   - Depth map (for 3D structure)
   - SDXL model
4. Downloaded result as current_ai.png
5. Updated camera background automatically
6. Saved generation to library with timestamp

USER NOW SEES THEIR FIRST AI GENERATION

PART 4: PROMPT SYSTEM (DETAILED)
================================================================================

4.1 HTML-STYLE TAG FORMAT
--------------------------

DESIGN RATIONALE:
• Simple, readable syntax
• Separates concerns (keywords, prompt, negative)
• Easy to parse with regex
• Graceful degradation (raw text works too)

SCHEMA DEFINITION:

```
# Keywords
<k>keyword1, keyword2, keyword3</k>

# Prompt  
<p>main image description here</p>

# Negative Prompt
<n>things to avoid</n>
```

PARSING RULES:
1. Lines starting with # are comments (ignored)
2. Empty lines are ignored
3. Tags are case-insensitive (<K>, <k>, <P>, <p>, etc.)
4. Content inside tags is extracted and trimmed
5. If no tags found, entire text used as prompt
6. Final positive prompt = keywords + ", " + prompt
7. Negative prompt sent separately to ComfyUI workflow

PROCESSING FLOW:
Text Editor → parse_prompt_tags() → build_prompt_from_template() 
→ process_prompt_builder() → workspace_setup.generate_ai_image_cloud()
→ ComfyUI Workflow (Node 25: positive, Node 7: negative)


4.2 KEYWORDS (<k> TAG)
----------------------

PURPOSE:
High-level modifiers that affect overall image style/quality.

EXAMPLES:
• Quality: 8k, 4k, high resolution, detailed, professional
• Medium: oil painting, photograph, 3D render, digital art
• Style: photorealistic, anime, concept art, impressionist
• Technical: sharp focus, bokeh, HDR, ray tracing

USAGE PATTERN:
<k>8k, photorealistic, professional photography, sharp focus</k>

BEHAVIOR:
• Prepended to main prompt with comma separator
• Optional (can be empty)
• Affects overall image quality/style
• Processed first by AI model

BEST PRACTICES:
• 3-7 keywords optimal
• Start with quality/resolution
• Add medium/style
• Include technical modifiers
• Avoid contradictions (e.g., "photorealistic, anime")


4.3 MAIN PROMPT (<p> TAG)
--------------------------

PURPOSE:
Describes the specific subject, scene, and details of the image.

STRUCTURE:
Subject + Action/State + Environment + Details + Composition/Lighting

EXAMPLES:

Simple:
<p>a dragon flying over a mountain</p>

Detailed:
<p>a majestic red dragon with spread wings flying over a snow-capped 
mountain range at sunset, golden hour lighting, volumetric clouds, 
cinematic wide shot, depth of field</p>

Complex:
<p>a medieval stone castle perched atop a cliff overlooking a misty 
valley, warm sunset light illuminating the towers, gothic architecture 
with detailed stonework, surrounded by dark forest, dramatic sky with 
storm clouds parting, wide-angle view from below, atmospheric perspective, 
rich color palette of oranges and blues</p>

ELEMENTS TO INCLUDE:
1. Subject: What is the main focus?
2. Description: Colors, materials, characteristics
3. Action/State: What is happening?
4. Environment: Where is it located?
5. Lighting: Time of day, quality of light
6. Mood/Atmosphere: Emotional tone
7. Composition: Camera angle, framing
8. Style Details: Specific artistic choices

BEHAVIOR:
• Required for generation
• Concatenated with keywords
• Sent to ComfyUI positive prompt
• Most important for AI model


4.4 NEGATIVE PROMPT (<n> TAG)
------------------------------

PURPOSE:
Specifies what to AVOID in the generation.

COMMON NEGATIVE PROMPTS:

Quality Issues:
blurry, low quality, low resolution, pixelated, noisy

Unwanted Elements:
text, watermark, signature, logo, UI elements

Deformations:
ugly, deformed, disfigured, bad anatomy, extra limbs

Style Conflicts:
cartoon (when wanting photorealism)
photorealistic (when wanting illustration)

Artifacts:
jpeg artifacts, compression, grain, chromatic aberration

USAGE PATTERN:
<n>blurry, low quality, watermark, text, deformed, ugly, bad anatomy</n>

BEHAVIOR:
• Optional (can be empty or omitted)
• Sent separately to ComfyUI negative prompt node
• NOT concatenated with positive prompt
• If empty, default negative used (configurable)

DEFAULT NEGATIVE (when tag empty):
"text, watermark, blurry, deformed, ugly, bad anatomy, worst quality, low quality"


4.5 LLM PROMPT REFINEMENT
--------------------------

FEATURE: "Refine Prompt (LLM)" button

PURPOSE:
Uses local LLM (via Ollama + ComfyUI) to enhance the main prompt (<p> tag).

REQUIREMENTS:
• GCS backend mode (not RunComfy)
• ComfyUI running with Griptape nodes
• Ollama installed with gemma3:4b model
• PromptRefiner.json workflow in workflows/ folder

USER FLOW:

1. Write basic prompt in <p> tag
   Example: <p>bilbo baggins in hobbiton</p>

2. Click "Refine Prompt (LLM)" button
   • UI freezes briefly (3-10 seconds typical)
   • Console shows progress

3. Wait for LLM processing
   • Workflow submitted to ComfyUI
   • LLM applies 8 prompt engineering rules
   • Enhanced prompt generated

4. Text editor updates automatically
   • <p> content replaced with refined version
   • <k> and <n> tags unchanged
   
   Example Result:
   <p>Bilbo Baggins, a middle-aged hobbit with curly brown hair and 
   a green waistcoat, sitting comfortably in his cozy hobbit hole in 
   Hobbiton, warm golden hour sunlight streaming through round windows, 
   detailed wood furnishings and patterned rugs, peaceful domestic 
   atmosphere, medium shot at eye level, 50mm lens, soft natural lighting, 
   earthy color palette of greens and browns</p>

5. User reviews and generates
   • Can edit further if desired
   • Or generate immediately with enhanced prompt

LLM PROMPT ENGINEERING RULES (8 total):
1. State subject first and clearly
2. Define medium and style
3. Specify framing and camera angle
4. Describe lighting and atmosphere
5. Add material and texture details
6. Keep prompt medium length (20-60 words)
7. Show mood through physical details
8. Output clean text only

TECHNICAL DETAILS:
• Blocking operation (UI freezes)
• 60 second timeout
• Polls ComfyUI every 2 seconds
• Extracts text from Node 17 or 19 output
• Handles character-array output format (Griptape quirk)
• Preserves <k> and <n> tags unchanged

OUTPUT PARSING BUG FIX:
The Griptape Display: Text node returns output as a list of individual
characters instead of a single string:

WRONG OUTPUT FORMAT:
{'INPUT': ['A', ' ', 'd', 'e', 't', 'a', 'i', 'l', 'e', 'd', ...]}

INITIAL BUG:
Code did value[0] which only got first character 'A'.
Result: Prompt became single letter!

FIX APPLIED:
Code now detects character arrays and joins them:
• Check if list items are single-character strings
• If yes: ''.join(value) to reconstruct full text
• If no: Use first element (normal behavior)

This handles both:
• Normal string output: "refined prompt text"
• Character array output: ['r','e','f','i','n','e','d',...] → "refined prompt text"

5.5 INFLUENCE/DENOISE CONTROL
------------------------------

PROPERTY NAME: texture_influence
LEGACY NAMES: depth_influence (old property, still exists)

LOCATION: Scene properties
UI VISIBILITY: NOT currently visible in N-panel (UI simplified)

RANGE: 0.0 to 0.7 (enforced maximum to prevent over-adherence)
DEFAULT: 0.25

INTERPRETATION:
• 0.0 = Full AI generation (100% denoise, ignore render)
• 0.25 = Balanced (75% denoise, use render for structure) ← DEFAULT
• 0.50 = Half influence (50% denoise)
• 0.70 = Maximum allowed (30% denoise, keeps render mostly intact)

BEHAVIOR:
• Inverted when sent to workflow: denoise = 1.0 - influence
• Controls how much AI deviates from your render
• Lower influence = more creative freedom
• Higher influence = closer to original render
• Max clamped at 0.7 to prevent "no AI" results

USE CASES:
• 0.0-0.2: Stylistic transformation, loose interpretation
• 0.2-0.4: Balanced AI + render structure (default range) ← RECOMMENDED
• 0.4-0.7: Strong adherence to render

CURRENT UX:
Influence not exposed in N-panel. Uses default 0.25.
This is a power-user feature that most users don't need to adjust.
Keeps interface focused on core workflow: prompt → generate → result.

7.2 UV TEXTURE GENERATION
--------------------------

FEATURE: Generate UV-mapped textures directly from 3D mesh.

LOCATION: Pie Menu → TOP (UV Texture)

TECHNOLOGY: Hunyuan 3D 2.1 (text-to-3D model in ComfyUI)

REQUIREMENTS:
• GCS backend mode (not RunComfy)
• .blend file saved (exports mesh)
• Selected object is MESH type
• current_ai.png exists (used as reference)

USER FLOW:

1. Model your 3D object
2. Select it (single object)
3. Generate AI reference image (any prompt)
4. Press Alt+W → Click TOP
5. Wait 1-2 minutes (background processing)

WHAT HAPPENS:

1. Export Phase
   • Selected mesh exported as .glb file
   • Format: <ObjectName>_<timestamp>.glb
   • Temp directory: %TEMP%/styleengine_uv/

2. Upload Phase
   • Upload .glb to ComfyUI server
   • Upload current_ai.png as reference
   • Server stores in input/ directory

3. Workflow Phase
   • Load objectUVTexture.json workflow
   • Patch Node 55: mesh file path
   • Patch Node 14: reference image
   • Patch Node 32: output name
   • Submit to ComfyUI queue

4. Processing Phase (1-2 minutes)
   • Hunyuan 3D 2.1 generates UV texture
   • Creates PBR material maps:
     - Base Color
     - Normal Map
     - Roughness
     - Metallic
   • Packs into single .glb with texture

5. Download Phase
   • Poll for completion
   • Download textured .glb
   • Save to temp directory

6. Import Phase
   • Import .glb back into Blender
   • Place at original object location
   • Material automatically assigned
   • Original object hidden (not deleted)

RESULT:
New object with fully textured, UV-unwrapped mesh.

USE CASES:
• Quick asset creation
• Texture generation for game assets
• Concept exploration (multiple variations)
• Product visualization

PART 9: BACKEND MODES

9.1 GCS (SELF-HOSTED COMFYUI)
------------------------------

FULL NAME: "GCS (Self-hosted ComfyUI)"

WHAT IT IS:
Direct connection to a ComfyUI instance running on:
• Google Cloud Services (GCS)
• Amazon Web Services (AWS)
• Local machine (localhost)
• Any server with HTTP access

CONFIGURATION:
• Server URL: http://IP:PORT
  Example: http://34.145.107.158:8188
  Example: http://127.0.0.1:8188 (local)

CONNECTION METHOD:
• Direct HTTP requests to ComfyUI Backend API
• POST /prompt (queue workflows)
• GET /history/{prompt_id} (check status)
• POST /upload/image (upload files)
• GET /view (download results)

ADVANTAGES:
• Full control over ComfyUI instance
• Access to all ComfyUI features
• Custom workflows supported
• No API usage limits
• Preview images (canny/depth) available
• UV texture generation works
• LLM prompt refinement works

DISADVANTAGES:
• Must maintain server instance
• Requires technical setup
• Costs for cloud hosting
• Must install dependencies (ControlNet, IPAdapter, etc.)

TYPICAL USE CASE:
• Studios with dedicated infrastructure
• Heavy users (many generations per day)
• Need custom workflows
• Privacy concerns (keep data on own servers)


9.2 RUNCOMFY CLOUD (SERVERLESS)
--------------------------------

FULL NAME: "RunComfy Cloud"

WHAT IT IS:
Managed cloud service that runs ComfyUI workflows on-demand.

CONFIGURATION:
• API Token: Long authentication string
• User ID: Your RunComfy account identifier

CONNECTION METHOD:
• RunComfy REST API (not direct ComfyUI)
• POST /deployments (ensure deployment exists)
• POST /run (submit workflow)
• GET /status (poll for results)
• Base64-encoded images in JSON responses

ADVANTAGES:
• No server maintenance
• Pay-per-use pricing
• Instant scaling
• Pre-installed ComfyUI dependencies
• Always latest ComfyUI version

DISADVANTAGES:
• API usage costs
• Limited workflow customization
• No preview images (canny/depth)
• No UV texture support
• No LLM refinement
• Requires internet connection
• Dependent on third-party service

TYPICAL USE CASE:
• Individual artists
• Occasional usage
• Don't want to manage infrastructure
• Rapid prototyping

----------------------

UV Texture Generation   | ✓                | ✗

PART 13: POWER USER WORKFLOWS
================================================================================

13.1 ITERATIVE REFINEMENT LOOP
-------------------------------

GOAL: Achieve perfect result through iteration.

WORKFLOW:

1. Initial Generation
   • Write basic prompt
   • Generate with default settings
   • Evaluate result

2. Adjust Prompt
   • Too stylized? Add keywords like "photorealistic"
   • Too realistic? Add keywords like "concept art, illustration"
   • Wrong composition? Add camera angle descriptions
   • Generate again

3. Tune Parameters
   • Too close to render? Lower influence (0.1-0.2)
   • Too abstract? Raise influence (0.4-0.6)
   • Low quality? Increase steps (25-30)
   • Generate again

4. Add Reference Images
   • Want specific style? Load style transfer reference
   • Want specific composition? Load composition reference
   • Adjust global strength and individual weights
   • Generate again

5. Refine with LLM
   • Prompt too vague? Use "Refine Prompt (LLM)"
   • Review enhanced prompt
   • Edit if needed
   • Generate again

6. Project and Archive
   • Happy with result? Project onto objects
   • Creates Iteration_###.png
   • Move on to next element

TIPS:
• Save often (preserves generation history)
• Take notes of successful settings
• Build library of reference images


13.2 MULTI-OBJECT TEXTURING
----------------------------

GOAL: Apply different AI generations to different objects.

WORKFLOW:

1. Model Scene
   • Create all objects (buildings, ground, props, etc.)
   • Position everything

2. First Object Set (e.g., Buildings)
   • Select buildings
   • Write prompt: "brick facade, weathered stone"
   • Generate
   • Project texture → Iteration_000.png

3. Second Object Set (e.g., Ground)
   • Select ground plane
   • Write prompt: "cobblestone street, worn, puddles"
   • Generate (overwrites current_ai.png)
   • Project texture → Iteration_001.png
   • Buildings keep Iteration_000.png (unaffected)

4. Third Object Set (e.g., Props)
   • Select props
   • Write prompt: "rusty metal, aged wood"
   • Generate
   • Project texture → Iteration_002.png
   • Previous objects unaffected

5. Final Composite
   • All objects have unique AI textures
   • Export scene or render final image

KEY ADVANTAGE:
Iteration system prevents textures from updating when new
images are generated, allowing complex multi-textured scenes.

16.1 WHAT WORKS WELL
--------------------

✓ PIE MENU AS PRIMARY INTERFACE
  • Faster than clicking through N-panel

  • More space than property field
  • Familiar interface (all Blender users know text editor)

  • Multi-line support
  • Syntax highlighting helps structure

✓ AUTOMATIC PROMPT PARSING
  • No toggle to remember
  • Tags optional (raw text works too)
  • Graceful fallback
  • Clear feedback in console

✓ REFERENCE IMAGE THUMBNAILS
  • Visual confirmation of loaded images
  • Quick identification
  • Professional appearance
  • Grid layout efficient

✓ CAMERA BACKGROUND DISPLAY
  • Result immediately visible
  • No need to open external viewer
  • Overlay with geometry shows context
  • Real-time update on completion


16.2 WHAT NEEDS IMPROVEMENT
----------------------------

⚠️ LLM REFINEMENT BLOCKS UI
  • Current: UI freezes 3-10 seconds
  • Better: Modal operator with progress indicator
  • Best: Async with cancel button

⚠️ NO VISIBLE GENERATION CONTROLS
  • Current: All settings hidden (uses defaults)
  • Better: Collapsible "Advanced" section with steps/influence
  • Risk: Users may not find controls when needed

⚠️ NO UNDO FOR PROMPT REFINEMENT
  • Current: LLM overwrites prompt, can't revert
  • Better: Store previous version, "Undo Refinement" button
  • Best: Full prompt history browser

⚠️ UV TEXTURE FEEDBACK IS CONSOLE-ONLY
  • Current: Background operation, check console
  • Better: Progress bar in N-panel
  • Best: Modal dialog with preview during processing

⚠️ NO GENERATION HISTORY IN UI
  • Current: Files saved but no browser UI
  • Better: Prev/Next buttons to navigate
  • Best: Grid gallery with thumbnails + metadata


16.3 USER PAIN POINTS (OBSERVED)
---------------------------------

1. "WHERE IS THE GENERATE BUTTON?"
   Solution: Moved to pie menu (Alt+W → BOTTOM)
   Reasoning: Pie menu is faster, reduces N-panel clutter

2. "MY PROMPT DIDN'T PARSE"
   Cause: Prompt Builder was disabled (old version)
   Solution: Made automatic (always parses, no toggle)

3. "HOW DO I ADJUST QUALITY?"
   Cause: Steps slider hidden
   Solution: Document Python access, or re-expose UI
   Note: 15 steps usually sufficient

4. "GENERATION SEEMS RANDOM"
   Cause: Influence at 0.25 gives AI creative freedom
   Solution: Document behavior, or expose slider
   Note: This is actually desired (AI interpretation)

5. "I CAN'T FIND MY GENERATIONS"
   Cause: Files in temp directory (volatile)
   Solution: Project library system saves timestamped copies
   Note: Need UI browser to make this discoverable


16.4 DESIGN DECISIONS EXPLAINED
--------------------------------

DECISION: Hide generation controls (steps, influence, resolution)
REASONING:
• Defaults work for 95% of cases
• Prevents users from setting steps too low (quality issues)
• Prevents users from setting influence too high (no AI)
• Reduces decision fatigue
• Faster onboarding

TRADE-OFF:
• Power users can't easily adjust
• Advanced workflows require Python console
• Less flexibility

MITIGATION:
• Document Python property access
• Consider "Advanced Mode" toggle in future
• Re-evaluate based on user feedback

---

DECISION: Prompt Builder always automatic (no toggle)
REASONING:
• Previous version had confusing "Enable Prompt Builder" checkbox
• Users forgot to enable it, prompts didn't parse
• Automatic detection is more intuitive
• Falls back gracefully to raw text

TRADE-OFF:
• None significant (just works)

---

DECISION: LLM refinement as blocking operation
REASONING:
• Simpler to implement than modal operator
• Manual operation (not frequent)
• 3-10 second freeze is acceptable for this use case
• Easy to upgrade to async later if needed

TRADE-OFF:
• UI freezes during refinement
• Can't cancel mid-operation
• No progress feedback during wait

MITIGATION:
• Future: Convert to modal operator
• Future: Add progress indicator
• Future: Add cancel button

---

DECISION: Pie menu for primary actions
REASONING:
• Faster than N-panel navigation
• Reduces N-panel clutter
• Standard Blender paradigm (used by many addons)
• Muscle memory develops quickly
• Works in all modes (Object, Edit, Sculpt)

TRADE-OFF:
• Requires learning keyboard shortcut (Alt+W)
• Not immediately discoverable for new users
• Some users prefer clicking visible buttons

MITIGATION:
• Quick start guide explains Alt+W prominently
• Pie menu is industry standard in Blender ecosystem
• First-time hint/tooltip could help

---

DECISION: Reference images visible in N-panel
REASONING:
• Core feature (not advanced)
• Visual thumbnails aid workflow
• Collapsible sections reduce clutter when not needed
• 15 slots is powerful for users who need it
• Can be ignored by users who don't

TRADE-OFF:
• Takes up vertical space in N-panel
• May seem overwhelming initially

MITIGATION:
• Sections collapsed by default
• Clear labeling (Style/Composition/Transfer)
• Thumbnails make purpose obvious
